# Data art with a creator

Start with what the creator wants the audience to notice, feel or understand. Read the current work and any supplied reference. Carry forward decisions the creator already made. A local revision should start at the relevant layer. When reproducing an existing work, use the original assets, geometry, type, proportions, copy and interactions.

## Find what is worth showing

Use AVA to understand the observations, units, relationships and unknowns that matter. For an open brief, use read-only queries to compare plausible findings when the first result alone does not settle the direction. Look for a relationship the audience can perceive in the work. Keep the grain, denominator and unknowns intact. Use [data and expression](references/data-expression.md) when the link between the data and the artwork needs work. Apply the chosen query at the current revision and inspect the resulting picture.

A visible mark can represent a row, an entity, a group or a derived relationship. Trace what drives it. Artistic decisions about form, material and layout can deepen the expression while leaving the observation identifiable. When you add a way to explore the data in the finished work, decide which records and values the audience can see. [Workbench operations](references/workbench.md#ava-in-the-finished-work) covers the AVA integration.

## Decide how the work should be seen

Use [visual direction](references/visual-direction.md) for a new composition or a broad redesign. When the brief leaves a consequential choice open, make small visual studies that differ in what they foreground or how the audience encounters the relationship. Choose from the rendered results. A change in palette tests palette; a change in grouping, hierarchy or point of view can test the whole proposition. Share a study when the creator’s judgment would change the direction.

Translate references into specific choices about silhouette, type, spacing, edges, layers, light or participation. Make the first encounter clear and give closer inspection something to reveal. Choose any interaction around what it lets someone discover or do. Check the real preview at its intended size and in a meaningful second state, then revise what falls short. Keep this work inside the implementation loop.

Load specialist knowledge for the decision at hand. Search with `npm run --silent visloom -- skills find --query QUERY`, then read the chosen entry and relevant resources. `skills read --id ID@VERSION --file PATH --start-line N --lines COUNT` reads a bounded excerpt. [Ink and drawn marks](references/ink-marks.md) is available for work that specifically calls for it. Check installed capabilities before choosing an implementation.

## Continue and deliver

Use [workbench operations](references/workbench.md) for CLI, source, revisions, capture and export. After a human edit, read the fresh context and changed files and preserve compatible edits and saved choices. Record confirmed intent in notes when it will matter in a later conversation. Show the actual work and the few decisions that matter. Deliver the requested preview or export and report unresolved issues plainly. Publish only at the creator’s request.
