# Data art with a creator

## Establish what the work should do

Start with the creator’s intent and the audience’s encounter. Ask what someone should feel, notice or be able to tell after seeing the work. A work can evoke a feeling, reveal the beauty of a data pattern, support a precise comparison, or do several of these in different parts of the same experience. An opening image can be expressive while the detail view lets someone read exact values. Use the precision the audience needs for each claim.

Use AVA to inspect the source and test the relationships worth showing. Explore plausible findings when the brief leaves the subject open. Decide what data actually determines in the work and what is an authored interpretation. Keep relevant units, missingness and uncertainty legible where the work makes a factual claim. Apply a selected query to the work when it changes the picture. See [data and expression](references/data-expression.md).

## Develop a visual language

Read supplied references as evidence of specific choices about color, typography, mark making, material, depth and motion. Decide which choices belong together in this work. Use [visual direction](references/visual-direction.md) when the look is open or the creator wants a substantial change. When alternatives would change what the work communicates, compare small rendered studies that make genuinely different choices. Review the opening and a closer view at the intended scale. Revise against the image itself.

Choose how to make and present the work after identifying its needs. A scene can be drawn or rendered offline and assembled on the web. A flat-looking work can use 3D, and a layered composition can combine illustrated and spatial elements. Use [production choices](references/production.md) when the tools, delivery format or division of work are open.

Load specialist knowledge for the decision at hand. Use `npm run --silent visloom -- skills find --query QUERY` and read the relevant entry and resources. Use `skills read --id ID@VERSION --file PATH --start-line N --lines COUNT` for a bounded excerpt.

## Continue the creator’s work

For a local change, work on the relevant layer and preserve accepted decisions. For a reproduction, use the original assets, copy, type, proportions and interactions. After a human edit, read the fresh context and changed files. Keep confirmed decisions in project notes when they matter for the next conversation. Use [workbench operations](references/workbench.md) for revisions, rendering and export. Show the actual work and explain the few decisions that affect it. Publish at the creator’s request.
