# Data sonification

Decide what a listener should be able to notice, such as the ordering of a sequence, the contrast between groups, or a significant change. Use AVA to verify the relationship and preserve units, record order and known gaps. State which sounds encode observations and which provide ambience or score.

Choose an audible mapping and range. For example, an ordered value might control pitch, an event interval might control timing, and a group might have a distinguishable timbre. Use a stable comparison baseline and provide an audible or visual key where it helps. If silence means missingness, distinguish it from an observed zero. When several streams compete, try sequencing or isolating them before layering them.

Listen to the actual output, including quiet values, close comparisons and crowded sections. Check whether the pattern survives without inspecting the code. When sound carries essential information, provide an alternate way to access that information in the intended medium. For web delivery, verify activation and volume controls on the viewing device. Check tool availability separately.

Sources: [Erie, a declarative grammar for data sonification](https://pages.cs.wisc.edu/~yeaseulkim/assets/papers/2024_erie.pdf) and [TwoTone](https://twotone.io/).
